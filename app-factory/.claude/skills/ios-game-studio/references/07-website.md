# Website, domain and support email (one domain per app)

Apple requires working Privacy Policy and Support URLs before submission; the marketing URL is optional but recommended.

## Steps

1. **Domain** (owner buys; ~yearly fee): prefer `<name>.com`, else `.app`, `.store`, `.game`. Turn on auto-renew. Check availability with domain tools if connected; otherwise ask the owner to check.
2. **Hosting**: Vercel (free Hobby). New project → import the app repo → it reads `vercel.json` (build `node tools/site/build.js`, output `site/dist`). Add the domain with `www` as primary and the apex redirecting to it. Set env vars `SITE_LEGAL_NAME`, `SITE_SUPPORT_EMAIL`, `SITE_GOVERNING_LAW` (keeps them out of git). The build refuses to deploy while any `[PLACEHOLDER]` remains.
3. **Email**: ImprovMX (free) forwards `support@<domain>` to the owner's inbox (MX + SPF records in Vercel DNS). Replies via Gmail "Send mail as".
4. **Pages** (`site/src/pages`): `index` (pitch, how it plays, App Store badge once live), `privacy` (what's stored, where, how to delete, Game Center, reminders, email contact), `terms`, `support` (FAQ + email), `404`. Rewrite the template copy for the new game; keep the privacy structure.
5. **SEO/AI files** generated by the build: canonical, Open Graph/Twitter tags, JSON-LD (WebSite + MobileApplication, no fake ratings), `robots.txt`, `sitemap.xml`, `llms.txt`, `site.webmanifest`, favicon set + OG image from the icon. The build fails on: title > 65 chars, description outside 70-170, not exactly one h1, banned brand words (`bannedWords` in `site.config.json`).
6. Link Privacy, Terms and Support from inside the app (first-run screen, home footer, Settings), plus a `mailto:` feedback link with app and iOS version in the body.

After launch: set `appStoreUrl` in `site.config.json` so the badge and structured data point to the store.
