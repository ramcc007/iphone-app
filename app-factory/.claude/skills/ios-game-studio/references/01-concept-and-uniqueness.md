# Phase 1: Concept and uniqueness

Goal: a game that a reviewer and a player both recognise in five seconds as *its own thing*. Crowded genres (number puzzles, match-3, word games, idle, solitaire) are allowed by Apple only when the app offers "a unique, high-quality experience" (Guideline 4.3(b)). Uniqueness is therefore both the product strategy and the review strategy.

## 1. From topic to twist

Start from the topic, then search for the twist in these places (combine two for stronger results):

| Lever | Question | NumFall example |
|---|---|---|
| Physics | What if pieces obey gravity, momentum, magnetism, stacking, flow? | Numbers fall to the lowest empty cell |
| Order | What if *when* you act matters as much as *what*? | Drop order is part of the puzzle |
| Constraint | Remove one freedom players expect (no undo, one colour, one row) | Columns, not cells |
| Perspective | Rotate, flip, layers, front/back, shadow | - |
| Time | Real-time pressure, turn limits, tide that rises each move | Clock on every level |
| Sharing of state | Two boards linked; moves echo; mirror | - |
| Theme fusion | A familiar rule set inside an unexpected fiction | - |
| Input | Swipe-drag, draw a path, hold-to-charge, tilt (with a non-tilt alternative) | Tap number, tap column |

Write 5+ candidate twists. Score each 1-5:

| Criterion | 5 means |
|---|---|
| Novelty | You cannot name an existing game that plays this way |
| Depth | Interesting decisions remain at level 100 |
| Clarity | Understood from one screenshot and one sentence |
| 30-second fun | Satisfying within the first 30 seconds, before any tutorial text |
| One-thumb | Playable one-handed on a phone; scales well to iPad |
| Screenshot appeal | The board looks colourful and alive mid-game |
| Review risk (inverse) | No gambling look, no user content, no kids-ads risk, not a skin of a known game |

Recommend the top scorer, but show the owner the top three with one-line pitches.

## 2. Loops

- **Core loop (seconds):** the single verb and its feedback (pick → drop → land → check).
- **Session loop (minutes):** levels or runs with a clear start, rising tension and a satisfying end (stars, time, score).
- **Return loop (days):** a daily challenge identical for everyone, a streak shown as a score (never as something to lose), achievements. No guilt, no fake urgency.

## 3. Content plan

- Levels are generated by code and **validated by code**: solvable, (unique solution if the genre needs it), difficulty measured by a solver metric, monotonic curve with small "breather" dips. Store levels as data checked into the repo.
- Group levels into named chapters of ~10 with a difficulty meter; early levels selectable freely so new players are never stuck.
- Plan 100+ levels per mode or an endless/daily generator; reviewers check for "enough content" (4.2 minimum functionality).

## 4. Naming

Rules:
- Original, short (ideally 1 word or a compound like NumFall), easy to say, works as a domain.
- Store name ≤ 30 characters; it must be unique in the App Store. If taken, a suffix like "NumFall: Number Drop" works while the Home Screen name stays short.
- Never include another game, company or trademarked genre word. Banned in anything public (extend per genre): Sudoku, Tetris, Candy Crush, Wordle, 2048, Minecraft, Pokémon, Scrabble, Monopoly, Solitaire brands such as "Microsoft Solitaire", Rubik, Lego, Uno, Jenga, Boggle, Chess.com, Lichess. Describe the rule instead ("each row, column and box holds each number once").
- Check: App Store search, Google, USPTO/WIPO (or say "not checked, owner to confirm"), and domains (.com, .app, .store, .game). Use domain tools if connected; never claim a domain is free without checking.
- Domain becomes the bundle ID prefix reversed: `numfall.store` → `store.numfall.app`. Bundle IDs are permanent once registered.

## 5. Risk check before Gate 1

| Risk | Guideline | Mitigation |
|---|---|---|
| Crowded genre clone | 4.3(b), 4.1 | Distinct twist, original art, explain it in review notes |
| Brand/trademark names | 2.3.7, 5.2 | Banned-word list enforced by site build and a grep before submission |
| Gambling look (spins, chests with random paid rewards) | 3.1.1, 5.3 | Rewards earned by play; odds disclosed if any randomness is ever sold |
| Kids audience | 1.3, 5.1.4 | Don't pick the Kids category; no third-party ads/analytics |
| User-generated content / chat | 1.2 | Avoid in v1 (needs reporting, blocking, moderation) |
| Accounts | 5.1.1(v), 4.8 | Avoid in v1; if added, in-app deletion and Sign in with Apple |
